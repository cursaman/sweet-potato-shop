# 온기담은 고구마

경주 산내에서 직접 재배한 고구마를 3kg·5kg·10kg 단위로 주문받는 Next.js 사이트입니다. 온라인 결제와 택배 추적은 포함하지 않으며, 제주·도서산간 주문은 받지 않습니다.

## 로컬 실행

```bash
npm install
npm run dev
```

전체 검증은 `npm run verify`로 실행합니다.

현재 기능의 유지·통합·제외 기준은 [`FUNCTION_AUDIT.md`](./FUNCTION_AUDIT.md)에 정리되어 있습니다. 신규 기능보다 관리자 화면 단순화와 실제 주문 흐름 안정화를 우선합니다.

실제 판매 시작 전 점검과 매일의 주문·입금·포장 처리 순서는 [`OPERATIONS_GUIDE.md`](./OPERATIONS_GUIDE.md)를 따릅니다.

## 주문 데이터베이스 연결

공유 Supabase 프로젝트 `edu-platform` 안에서 기존 서비스와 섞이지 않도록 `sweet_potato_orders` 전용 테이블을 사용합니다.

1. Supabase SQL Editor에서 `supabase/migrations`의 SQL 파일을 번호 순서대로 실행합니다.
2. `.env.example`을 참고해 `.env.local`에 Supabase 정보와 카카오뱅크 입금 안내 문구를 설정합니다.
3. 개발 서버를 다시 시작하고 `/admin`의 `운영 설정 점검`에서 모든 필수 항목이 정상인지 확인합니다.
4. 본인 연락처와 실제 받을 주소로 시험 주문을 1건 접수합니다.
5. 주문번호·판매가·재고 감소·입금 알림·관리자 입금 확인·포장 상태를 순서대로 확인합니다.
6. 미입금 상태에서 취소 시험을 할 때는 주문조회 화면의 취소 기능을 사용해 재고가 복구되는지 확인합니다. Table Editor에서 주문을 직접 삭제하면 재고가 자동 복구되지 않습니다.

`ADMIN_PASSWORD`를 설정하면 `/admin`에서 입금 확인 요청 주문을 조회하고 실제 은행 내역을 대조한 뒤 입금 완료로 변경할 수 있습니다. 관리자 비밀번호는 공유하거나 저장소에 커밋하지 마세요.

현재 마이그레이션은 `001`부터 `009`까지 번호 순서대로 적용합니다. 주문·입금 알림·원자적 재고·고객 취소·관리자 재고 수정·포장 상태·비용 설정·판매가 설정·시험 데이터 초기화를 각각 추가합니다. 주문 취소 시 확보 수량도 자동 복구됩니다.

## 운영 통합 점검

- Vercel 환경변수: `SUPABASE_URL`, `SUPABASE_SECRET_KEY` 또는 `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_PASSWORD`, `BANK_TRANSFER_GUIDE`
- 관리자 점검: 주문 테이블, 재고 테이블, 가격·비용 설정, 재고 수정 RPC, 주문 생성 RPC, 고객 취소 RPC
- 실제 주문 1건: 운영 데이터를 변경하므로 임의 고객정보 대신 관리자가 직접 사용할 시험 정보를 입력합니다.
- 확인 후 처리: 미입금 시험 주문은 정상 취소 절차로 종료합니다. 입금 확인 완료 주문은 매출 기록이므로 임의 삭제하지 않습니다.

서비스 역할 키는 브라우저 코드, GitHub 또는 공개 환경변수에 넣으면 안 됩니다. 주문 입력값과 가격은 Next.js 서버에서 다시 검증하며, 익명 사용자와 일반 인증 사용자는 주문 테이블을 직접 읽거나 쓸 수 없습니다.
